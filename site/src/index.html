01 / Divergence from reference

Synonymous and non-synonymous codon differences from reference, each normalized by the number of codons the two sequences can be compared at — those where both carry three unambiguous bases, plus those an insertion or deletion touches. An indel counts as one non-synonymous difference per codon it touches.

This is an uncorrected count-based similarity metric. It is not dN/dS, it applies no per-site normalization and no multiple-hit correction, and it is not an evolutionary rate.

02 / Nucleotide distance

Multidimensional scaling of pairwise nucleotide distance, each pair normalized by the number of alignment columns where both sequences carry an unambiguous base. Position here comes from every other sequence rather than from a reference, and needing no reading frame, this view adds the two non-coding regions.

Both axes are scaling coordinates, not measured quantities: their units are arbitrary, their signs are fixed only by convention, and only relative position carries meaning. Two dimensions cannot hold all of the distance structure, and the figure states how much of it they do hold.

03 / Nucleotide phylogeny

Neighbor joining on the same distance matrices as the view above, so the tree and the embedding cannot disagree about how partial overlap was handled. Rooted on Sabin for poliovirus, midpoint for non-polio.

Branch lengths are observed differences per position compared. They are not substitutions per site, not corrected for multiple hits, and not time, so a branch twice as long means twice the observed difference and nothing further. Vertical position is a place in the ladder, not a measured quantity, which is why that axis carries no scale.

04 / Protein distance

The same scaling as view 02, over translated amino acid distance, each pair normalized by the number of codons where both sequences carry three unambiguous bases. Read it against 02: structure that survives translation is structure in the protein, and structure that disappears was synonymous all along.

Proximity here is protein similarity over the codons two records share. It is not sequence identity, and it is not evidence of common ancestry: unrelated lineages under similar constraint can arrive at the same residues.

05 / Protein phylogeny

The same three coding regions, built from translated amino acid distance. A synonymous change moves nothing here, so sequences that reached the same residues by different codons sit at zero distance and the tree joins them, whether or not they share recent ancestry.

This tree groups by residue identity, which is not the same thing as descent: it will join lineages that arrived at the same residues independently, and one amino acid change separates two sequences that dozens of synonymous changes would not. Read it as a statement about the protein, and read 03 for ancestry.

06 / The release, and what is wrong with it

Every number on this page is recomputed from the shipped release at build time, so it cannot drift from the data. That includes the problems: this page reports data-quality issues and never repairs them.

Population per view

Coverage is bimodal rather than tapered — a region is either near-complete or absent — so the four panels of a figure are four different populations. P1 is fully populated because a record enters an alignment by capsid typing.

Coordinate frames and reference choice How partial sequences are made comparable, and what stands in for Sabin when there is no vaccine reference.

Poliovirus records are read in their own serotype's alignment, whose reference-frame line is exactly Sabin genome coordinates, so the shipped region coordinate map applies without inference. Non-polio records are read in the genus-wide alignment, which contains the Sabin genomes and whose coding block is a codon alignment; the polyprotein cleavage boundaries are projected from Sabin 1 through it. Cleavage sites are homologous across the genus, and the projected region widths reproduce the per-serotype widths exactly.

Non-polio enterovirus has no vaccine reference, so divergence is measured against a consensus of the record's own virus type. I give it no broader fallback than that: an enterovirus species holds dozens of serotypes that differ by a quarter of their capsid, so a consensus across one is a chimera, and distance from it would fold "how unusual is this type" into "how far has this sequence drifted" on a single axis. A record whose type is unrecorded, or holds too few sequences to support a consensus, is therefore reported unmeasurable in this view rather than compared to something that does not mean the same thing. Distance and phylogeny need no reference, and keep every record.

A consensus built from few sequences is defined largely by those sequences, so they sit closer to it than a well-populated type would. Each reference label carries the number of sequences that built it.

A known limitation, not yet fixed: a type's consensus carries a base wherever any of its sequences does, so for a large and fragmentary type it is a union of coverage rather than a typical genome. A partial record then reads as deleted at every position it does not span but some relative does, which inflates its non-synonymous rate. Counted live from this release, — which is why some of them sit far right and high with almost all of that distance coming from indels rather than substitutions. The consensus stands in for per-type reference sequences the release does not yet carry, and I would rather fix that by curating them than by patching the metric here.

A record is compared to its reference only where both carry an unambiguous base, so missing left and right tails cost coverage rather than counting as difference, and an ambiguity code lowers the denominator instead of inventing a mismatch. Insertions and deletions inside the covered span count as one non-synonymous difference per codon they touch, and those codons join the denominator — which is what keeps both axes inside zero and one. A record whose indels shift the reading frame is marked rather than translated.
